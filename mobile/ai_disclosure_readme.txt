## 3. Task editing can overwrite data

`EditTaskPageState` has several related problems:

- Controllers are recreated in `build`, resetting text/cursor on rebuild.
- The submitted state starts with empty/default values rather than the task’s values.

- Save pops immediately with a **Future**, before the server responds.
- Both edit callers navigate to an unregistered route and refresh immediately, without `setState`.

A safe approach is to initialize controllers and values once in `initState`, dispose controllers in `dispose`, and submit only fields being edited. Change `patchTask` to accept a map of changed fields:

```dart
Future<Task> patchTask(String id, Map<String, dynamic> changes) async {
  final response = await http.patch(
    Uri.parse('$baseUrl/api/tasks/${Uri.encodeComponent(id)}'),
    headers: _apiHeaders(authenticated: true),
    body: jsonEncode(changes),
  );

  if (response.statusCode != 200) {
    throw Exception('Task update failed: ${response.statusCode}');
  }
  return Task.fromJson(
    Map<String, dynamic>.from(json.decode(response.body) as Map),
  );
}
```
